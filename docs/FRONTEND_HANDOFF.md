## 设计还原

以用户提供的两张设计图为主，复用 `public/assets` 的品牌、建筑背景、类型图标、模块标记和专题卡片整图。`awesome-design-md/design-md/airtable/DESIGN.md` 只用于间距、字体层级和可访问交互参考；其品牌色、卡片视觉和移动端方案均不覆盖用户原稿。

- 品牌蓝 `#2575ff`；主体深色文字；浅蓝、青色、紫色区分报表类型，暖橙区分目录。
- 保留首页左右主次列、工作台四列、专题三列、字典侧栏加三列卡片。
- 根字号固定16px，正文最低12px，标题按有限范围变化；删除运行中的 JS 根字号适配。原来的 JS 以100px为根基准，与 Tailwind/CSS 的16px体系冲突。
- 工作台与专题固定为本次调整前的模块高度：1280–1599px视口分别为471/351px，1600–2199px为469/324px，2200px以上为555/396px。内部卡片用 flex 换行，超出模块时内部滚动；蓝色滚动条仅在悬浮或滚动时显示，停止滚动800ms后隐藏。整页高度不固定，较矮 iframe 允许自然纵向滚动。
- 搜索框宽度在680–1120px间随视口调整，高度为29px；输入与按钮文字为13px，字典入口和视图按钮同步缩小。下拉层最高400px，列表内部滚动。字典左右面板底部随内容同步对齐。公告行内边距4px，日期与置顶标记垂直居中并保留独立列；标题比原版小1px，超过12个字符截断并加 `......`，悬浮和详情显示完整标题。
- 宽度以 iframe 视口为准，1280/1440/1920/2560px 验证；小于1280px保留桌面宽度并横向滚动，无移动导航或移动卡片逻辑。
- 新增收藏、详情、空态、加载、错误、键盘焦点等交互状态不在原静态图中，以原配色和组件语言补齐。

右上角提供三种显示模式，首页与报表字典共用选择：

| 模式 | 行为 |
| --- | --- |
| 当前布局（默认） | 保留上述桌面断点、模块高度和最小1280px宽度 |
| 宽度自适应 | 以1920px桌面布局为基准，整体按嵌入区域宽度等比例缩放，内容较高时纵向滚动 |
| 双向自适应 | 以1920px画布为基准，横纵独立缩放至嵌入区域的完整宽高；不留边，文字和图标也随两轴比例拉伸 |

缩放覆盖页面字体、间距和图标，不增加移动端布局。弹窗仍按正常尺寸显示。页面宽度、字体和断点统一按画布容器计算，避免缩放时再次触发小屏断点。窗口尺寸或内容高度改变时重新计算比例；切换模式不卸载页面，不重置筛选、Tab、收藏和10分钟刷新缓存。模式保存在 `ynby.portal.display-mode`，存储受限时只在当前页面会话中保留。

模式切换使用浏览器 View Transition，过渡280ms；连续操作以最后选择为准，系统要求减少动态效果或浏览器不支持时直接切换。背景挂在门户容器，避免公告弹窗锁定页面滚动时按变化后的文档宽度重算。全部公告独立加载、分页，首页列表保持原样；从列表打开详情时使用嵌套弹窗层级。内部滚动条使用 Ant Design 默认蓝色 `#1677ff`，仍仅在悬浮或滚动时显现。

模式按钮组可收起，收起后显示当前模式；展开状态保存在 `ynby.portal.modes-collapsed`。首次进入展示 Coach Marks，可跳过、按 Esc 关闭或完成，之后可通过右上角“使用引导”重看。已阅标记为 `ynby.portal.guide.v1`；存储被禁用时不自动弹出，手动入口仍可用。

点击搜索框显示报表、标签、指标三类下拉层。标签使用业务模块，指标使用 core_metrics；默认内容来自最近打开的报表缓存。输入后延迟200ms请求授权搜索结果，旧请求取消；确认搜索才写个人历史。每类最多20条，支持清空与刷新后恢复。下拉层挂在未缩放的 body，防止被画布裁切；支持方向键选结果、Enter确认、Esc及外部点击关闭、Tab访问分类和历史。

## 已实现行为

首页搜索跳转全局报表字典；报表名称、指标、Owner、数据源可搜索。筛选同组OR、组间AND，重置和计数联动，状态写入URL，列表/卡片切换共用结果。工作台三种分类实际切换数据，常用按近30天访问量排序。收藏在所有入口共用状态，失败保持原状态。专题根据ID下钻，支持事业群切换、任意深度面包屑返回。公告可查看全部和正文。归档报表只展示详情，禁止打开。

工作台首次加载时读取三类列表，Tab 直接切换内存缓存。各已挂载数据区每10分钟静默刷新，不重置当前 Tab、专题目录或滚动位置；临时失败保留已有内容，登录或权限失效则清除对应数据并显示错误。收藏成功响应同时更新收藏 ID 和工作台缓存，已发出的旧刷新结果不会覆盖本次收藏操作。

## 运行与检查

```powershell
npm run dev
npm run type-check
npm test
npm run build
```

`npm run build` 生成 `out/`；不要用 `next start` 托管静态导出。生产使用静态服务器及同源反向代理。本轮未修改现有生产部署配置，部署前需按实际挂载路径配置静态资源；当前预览按域名根路径提供门户。

浏览器回归（使用宿主机已有 Playwright，避免为前端引入测试运行依赖）：

```powershell
$env:PLAYWRIGHT_MODULE='已安装的 playwright 绝对目录'
$env:BROWSER_CHANNEL='msedge'
$env:PORTAL_URL='http://localhost:3000'
node scripts/check-portal-ui.cjs
```

脚本检查四种桌面宽度的横向溢出、固定高度、内部滚动、公告对齐、字典底部、图片加载及主要交互；同时验证三种显示模式、模式记忆、路由切换、原尺寸弹窗、iframe尺寸变化和存储受限场景。截图写入 `artifacts/qa/`，不加入Git。逻辑检查还覆盖累计访问量边界、过滤计数、树循环终止、非法链接、HTTP错误和平台打开参数。

`node scripts/check-portal-layout.cjs` 额外启用浏览器真实滚动条，在 iframe 中逐帧检查单条公告、全部公告及嵌套详情的背景与布局尺寸，验证紧凑搜索栏、切换动画、快速切换、减少动态效果和旧浏览器回退。设置 `PORTAL_LIVE_POC=1`、`PORTAL_URL` 为 Railway 地址可直接验收云端。

验证浏览器 HTTP 适配层时，以 `NEXT_PUBLIC_PORTAL_MODE=api` 启动前端，在检查脚本的进程中设置 `PORTAL_MOCK_HTTP=1`（由 Playwright 拦截接口返回模拟数据）。同一脚本会额外验证 Tab 切换零读取请求、10分钟刷新、刷新失败保留内容和会话过期清除内容，无需真实后端。Railway 后端验收使用 `backend/test/poc.mjs`，不拦截 HTTP。
